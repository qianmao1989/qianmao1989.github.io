LLM Agent 的 12 个底层原理

从消息结构到多智能体协作，一张图看懂 AI 是怎么工作的

← 返回草稿箱

🔥 一句话总结

大模型不是魔法，是一套层层堆叠的技术栈。这 12 个原理构成了现代 LLM Agent 的完整骨架，缺一不可。

1Messages — 一切都是消息

基础通信协议

AI 和你的每一次对话，底层都是 messages 数组。每条消息包含两个字段：role（system / user / assistant / tool）和 content。这是 LLM 的通用协议，理解了这个就理解了 AI 的"语言"。

📌 实务：system 放规则，user 放问题，assistant 放回答，tool 放外部调用的结果。OpenAI 定义的这个标准，现在几乎所有大模型都在用。

2上下文窗口 — AI 的记忆容量

限制成本

LLM 能"看到"的历史是有限的，这个上限就是上下文窗口（如 128K tokens）。超出窗口的内容会被截断，就像人只能记住最近几天的对话。

📌 实务：窗口越长越贵。用好 prompt cache 可以大幅省钱——把稳定内容（system prompt）放前面，变动内容放后面，命中缓存的部分不收费。

3System Prompt — AI 的"宪法"

核心约束

System prompt 是 messages 中 role: system 的那一条，定义 AI 的身份、边界、行为规则。它是对话中最底层的规则，优先级最高。

📌 实务：写好 system prompt 比调参数更重要。好的 system prompt = 你是谁 + 你能做什么 + 你不能做什么 + 怎么说话。

4思维链 — 拆开想，才能想清楚

推理能力

Chain of Thought (CoT)：让模型在输出答案之前，先"自言自语"地推演一遍。把复杂问题拆成小步骤，每步验证，最后汇总。

📌 实务：复杂计算、多条件任务、逻辑推理，让 AI 先列步骤再回答。DeepSeek-R1、OpenAI o1 等推理模型的内核就是思维链。

5Few-Shot — 给例子，比说要求更管用

提示工程样本

在 prompt 里放几个输入→输出的例子，模型就能模仿着做。比用自然语言描述"你要这样这样"更有效。

📌 实务：格式要求、分类任务、特定风格输出，给 2-3 个例子往往比写 500 字说明更精准。

6预填充 — 给 AI 起个头

技巧控制

在 assistant 回复还没开始之前，先给它写一个开头（如 {"role": "assistant", "content": "好的，我来分析"}），强迫它按你设定的方向走。

📌 实务：防拒绝、锁定格式、跳过废话。比如预填 ```json { 就能让模型直接输出 JSON 而不闲聊。

7停止序列 — 刹车机制

控制安全

设定一个关键词（如 </output> 或 STOP），模型碰到这个词就立即停止生成。防止跑偏、防止输出多余内容。

📌 实务：在 Tool Use 中尤为重要——模型输出工具调用后立刻刹车，等外部结果回来再继续。

8Tool Use — AI 的"手"

核心能力行动

Function Calling：模型不只是说话，还能调用外部工具——查数据库、发邮件、执行命令、读写文件。

📌 实务：Tool Use 让 AI 从"嘴炮"变成"能做事的 Agent"。关键是定义好工具的描述和参数 schema，模型才知道什么时候用什么工具。

9RAG — 外挂知识库

检索知识

Retrieval-Augmented Generation：模型的知识截止于训练日期，要访问最新或私有知识，先检索→再回答。把相关文档塞进上下文窗口，模型就有据可查。

📌 实务：RAG = 向量搜索 + 上下文注入。先搜到相关片段，再拼进 prompt，模型就能引用最新信息回答。

10ReAct — 思考+行动循环

框架决策

Reasoning + Acting 的缩写。AI 不是一次性回答，而是循环：思考→行动→观察结果→再思考→再行动，直到完成任务。

📌 实务：这才是真正的 Agent 行为。Agent 不是"一句话回答"，而是"多轮调用工具、不断修正"。每次 Tool Use 都是一次 ReAct 循环。

11幻觉 — AI 最头疼的问题

问题对抗

模型会自信地编造不存在的事实，这就是幻觉。因为 LLM 本质是"下一个词预测器"，不是"事实验证器"。

📌 实务：对抗幻觉三件套 — ①能查的不猜 ②能跑的不想 ③能验证的不信任自己。数字用脚本跑，文件用工具读，引用先搜索确认。

12Multi-Agent — 团队协作

架构协作

一个 Agent 不够，多个 Agent 分工协作。每个 Agent 有自己的 system prompt、工具、职责范围，互相配合完成复杂任务。

📌 实务：比如一个 Agent 管表格、一个 Agent 识图、一个 Agent 写代码、一个 Agent 管对外通信。各司其职，通过共享记忆或消息传递协调。

🧩 它们之间的关系

Messages (1) 是通信协议 → System Prompt (3) 定义边界 → 上下文窗口 (2) 限制容量

思维链 (4) + Few-Shot (5) + 预填充 (6) + 停止序列 (7) 是提示工程四件套

Tool Use (8) + RAG (9) 给 AI 装上手脚和外脑

ReAct (10) 让手脚协调运转 → 对抗幻觉 (11) 保证不出错

Multi-Agent (12) 是最终形态：多个这样的智能体组成团队


从一条消息到一支 AI 军团，这就是现代 LLM Agent 的完整地基。
